# 框译 · 漫画华文翻译层

本机漫画阅读器：输入 MangaDex 或 Naver 作品目录／章节链接 → 选章 → 翻页或连续滚动 → 英文或韩文翻译成华文 → 中文叠在原来的对白框内。来源语言取自章节元数据。Naver 按网站原有图片分段阅读，不需要逐页上传截图。

## 上传到 GitHub

可以把本目录作为**源码仓库**上传。`.gitignore` 已排除本机缓存、第三方漫画样张、抓取调试文件、密钥文件及 iOS 构建产物。上传前用 `git status` 或 GitHub Desktop 的变更列表确认没有漫画原图或 API Key；如果使用 GitHub 网页手动拖拽文件，需自行跳过这些文件，因为 `.gitignore` 不会过滤网页上传。公开仓库不附带 `samples/`，因此首页的人工漫画样张入口在新克隆的副本中不可用，正常导入章节和自制排字示例仍按各自说明使用。

GitHub 仓库链接用于分享代码，**不能直接当成 iPhone Chrome 的在线翻译网址**。GitHub Pages 不运行本项目的 Python/FastAPI 服务；网页版要供他人通过网址使用，需要另行部署服务、配置 HTTPS，并决定如何提供云端翻译凭证。`ios/` 使用设备端 ML Kit，不靠网页服务器，但要先在 Mac 上编译、签名和安装；公开给其他 iPhone 用户安装还需走 Apple 的分发流程。目前 iOS 原型尚未真机验证。

iPhone/iPad 原站浏览器源码在 `ios/`。它通过 WKWebView 直接打开原网站，保留原站目录、章节链接和网页后退，停住后自动翻译当前漫画画面；与本机网页版的 MangaDex 目录适配器不同。iOS 版现在默认使用 Google ML Kit 在设备上识别英文并译为华文，无需按页调用付费翻译 API；原有图片模型保留为可选云端模式。本机模式仅尝试处理漫画图像内、背景平整的文字，无法安全覆盖时保留英文。iOS 源码尚未在 Mac/Xcode 编译或真机验证，详情看 `ios/README.md`。

首页 `/` 是黑底漫画阅读器，设置与校对在弹窗中。原图片编辑器在 `/editor`，仍可处理截图或长图并导出 PNG。

## 像漫画网站一样阅读

1. 首页或地址栏输入 MangaDex 的 `/title/…` 或 Naver 的 `/webtoon/list?titleId=…` 目录链接，回车后选章节；也可直接打开对应章节网址。阅读时按「↶ 目录」返回同一作品选择其他章节，无需粘贴下一章链接。MangaDex 目录每批 100 条，Naver 每批 30 条，按来源页码翻阅。
2. 默认单页翻页；可使用左右箭头、键盘方向键、或切换连续滚动。菜单里可调整阅读宽度。
3. 点「配置自动翻译」或「☰ 阅读设置」，填写 API Key 和支持图片、结构化输出的模型名称，保持「自动翻译正在阅读的页面」勾选并点「完成」。自动翻译默认开启，图片加载完成后自动处理当前页；翻页、连续滚动或换章后也会继续，无需逐页点按钮。
4. 仅串行翻译正在阅读的页面，快速翻页会先等待约 650ms，再选择当前页；已译页直接恢复当前会话译稿，不重复请求。切回原文、进入目录、打开设置或切到后台会暂停新请求。取消勾选后当前已发出的请求仍会完成；失败关闭自动翻译，修正设置后点「继续自动翻译」恢复。翻译层是独立透明 Canvas，只绘制原字位置的小范围底色和中文，原始 `<img>` 始终保留，滚动与链接点击照常。
5. 点击页下方「校对」可以修改译文和字号。复杂背景修复或框的位置调整可继续使用 `/editor`。成功的译文、坐标和校对修改会保存到此浏览器，刷新或重新打开同章时恢复，默认继续显示华文。最多保存最近 5 章、约 4MB；空间不足时淘汰较早章节，保存失败会显示提示。不会保存 API Key、原图或设置中的私人输入。清除浏览器数据会清除译稿，存储不可用时仍可在当前会话阅读。

本次指定的 MangaDex 章节是 Fight Class 3 第44话的英文版，共26页。已核实其英文目录当前共109条，支持100+9条分页。首页提供第2页两处对白的人工试译样张，其余文字保留英文；此样张用于验证阅读与排字效果，并非完整章节翻译，也不是自动模型质量测试。未配置 API Key 时可阅读原文与样张。

章节打不开、已下架、需要登录／付费、没有公开图片或图片服务器异常时，会显示错误，不绕过访问限制。Naver 适配器只读取公开目录和原网站阅读区的图片，不处理 Cookie、登录或年龄验证。当前网址导入支持 MangaDex、Naver；其他网站使用图片编辑器或 iOS 原站浏览器源码原型。

用户指定的 Naver 第 39 轮在正序目录第 3 页，发布条目编号分别是 `70` 和 `71`，标题是 `ROUND 39. 심하민 (1)/(2)`。本地阅读入口为 `/?chapter=naver-701535-70&page=1`；返回目录会保留在对应目录批次。导入、原图读取和模拟译稿保存测试不代表已经进行真实 API 翻译。

在 `/editor` 点击“打开排字示例”可在不调用模型的情况下查看效果。示例是自制画面和预设译文，并非真实自动翻译结果。

本次另附你指定的 Naver 第一集开头两句的短样张：点击“打开第一集试译样张”。译文和位置经过人工设置，未调用付费模型；不能作为自动识别或自动翻译质量的证明。韩文人名 주대각 已按用户提供的[中文版第2页](https://m.manhuagui.com/comic/52303/753891.html#p=2)统一为“朱大觉”，这是沿用参考版本的译名，并非已核实的官方汉字名。图片与样张项目在 samples 文件夹中，漫画来源是你提供的链接。

### 现有中文版参考

选择“译名与语气参考 → 格技3班 · 现有中文版对照”，每次翻译时会把 `references/fight-class-3.json` 中的译名、语气规则和两句短对照传给模型。用户术语表优先；遇到语义冲突，遵循韩文原文。

这是推理时的参考配置，不是模型微调或权重训练。目前仅人工核实第一话第2页的开头两句，不能称为整部漫画的训练集。后续新增参考应保存对应原文、自己的译文、出处和人工校对状态，再用独立未见样本评估质量。

## 自动翻译

在「阅读设置」中输入 OpenAI API Key，以及账户可用、支持图片输入和 Structured Outputs 的模型名称，点「完成」后即自动开始。密钥在本地设置填写，不要发到聊天中。模型名称没有硬编码默认值，避免假定账户权限和预算。

也可在启动前配置环境变量：

```powershell
$env:OPENAI_API_KEY = '你的 API Key'
$env:COMIC_MODEL = '你的模型名称'
python server.py
```

密钥只在当前会话或环境变量中使用，不写入浏览器存储、项目文件或日志。自动翻译会把阅读中的图片、剧情背景、人名术语和前段对话发送给 OpenAI，费用取决于模型和图片大小。API 请求关闭 response 存储（store=false）；这不代表提供方完全不保留服务日志。

一次只处理一张图：原文件最大 20MB，3000 万像素；长图分成带 400px 重叠的 1800px 图段，最大 12 段。按顺序传递先前对白，减少人名、称呼和上下文不一致。超过限制时分段上传，不把整话缩成无法辨认的小图。接口不会自动重试，失败重试可能重新产生费用。

## 校对与排字

1. 上传、拖入图片，或 Ctrl+V 粘贴截图；直接使用截图可避开网页登录、跨域及动态加载问题。
2. 填写人名术语表、必要剧情背景，点击“识别韩文并翻译”。
3. 点击区域编号，核对识别到的韩文和中文。模型不确定的内容会提示核对，提示不能证明其他内容必然准确。
4. “原字擦除区”只覆盖韩文文字；“中文排字区”控制中文布局。两者可分别拖动和用右下角缩放，数值也可编辑。
5. 字号 0 表示自动换行和适配，保留完整译文，不删句子或偷偷截断。放不下会保留原图并阻止导出，需调整框或字号。空译文和停用区域不擦原字。
6. 对照“原图”，检查框线是否完好，然后下载中文 PNG。导出无编辑框。
7. 保存项目可保留原图、译文、坐标、背景和术语；打开项目继续修改。项目不含密钥。

## 当前限制与验证状态

- 本机网页版支持 MangaDex、Naver 作品目录／章节网址和浏览器译稿保存；它是独立阅读器。保留原网页导航的实现另在 iOS 原型源码中，iOS 译稿目前仍只保留在 App 会话内。网页版仍使用需 Key 的云端图片模型；ML Kit 设备端路线仅在 iOS 源码中。
- 白底/纯色对白框使用紧凑矩形覆盖；不会重画整个对白框。彩色纹理背景、特效字需要另外修复。模型坐标仍可能覆盖到画面，导出前要核对。
- 模型视觉定位、韩文识别与翻译会出错，无法保证出版级准确度。提供连续截图、剧情背景、固定人名能改善一致性；仍需人工校对。
- 已提供本地排字和服务端管线回归测试。模拟模型结果只验证接口接线与坐标转换，不能用于证明真实翻译质量。
- 实际模型调用需要用户的 API Key；未配置时只可使用手动排字和预设示例。
